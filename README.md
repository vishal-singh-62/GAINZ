# GAINZ

### Personalized Workout & Diet Planner with AI

GAINZ is a personalized fitness planning web application designed to help students create workout and meal plans based on their individual goals, lifestyle, available equipment, dietary preferences, culture, and budget.

The project combines a rule-based fitness planning system with AI-powered recommendations to make the generated plans more personalized and practical.

---

## 🎯 Problem Statement

Most fitness applications provide generic workout and diet plans that do not always consider an individual's:

- Fitness goals
- Activity level
- Available training days
- Available equipment
- Dietary preferences
- Cultural food habits
- Food budget
- Personal requirements

Students in particular may need fitness plans that are practical, affordable, and compatible with their daily schedules.

GAINZ aims to address this by generating personalized workout and meal plans based on the user's profile and preferences.

---

## ✨ Features

### 👤 Personalized Profile

Users can provide information such as:

- Name
- Age
- Gender
- Height
- Weight
- Fitness goal
- Activity level
- Training days per week
- Available equipment

### 🏋️ Workout Planning

GAINZ generates workout plans based on:

- Fitness goal
- Activity level
- Training frequency
- Available equipment

### 🍱 Personalized Diet Planning

The meal planning system considers:

- Food/cultural preference
- Dietary restrictions
- Weekly food budget
- Fitness goal

### 📊 Progress Tracking

Users can record:

- Date
- Weight
- Progress notes

GAINZ also provides a weight chart, a 30-day activity calendar, workout completion and streak tracking, and a daily water tracker.

### ☁️ Accounts & Cloud Sync

- Email and password sign-up / sign-in, with password reset, through Supabase Auth
- Profile, workout plans, diet plans, progress, workout completions and water intake are saved to Supabase
- Data is isolated per user with Row Level Security and follows the user across devices
- localStorage is used as a fast local cache; the cloud copy is authoritative after sign-in

### 🤖 AI-Powered Assistance

GAINZ includes an AI coach powered by the Google Gemini API (called through the Node server, so the API key never reaches the browser). It can help users:

- Ask questions about their workout
- Replace exercises
- Make workouts easier
- Suggest meal alternatives
- Ask about their progress

### 💡 Insights

After generating a plan, users can see BMI, estimated ideal weight, BMR, daily water goal and a macro breakdown, along with goal-specific recommendations. These are calculated with standard formulas (Mifflin-St Jeor, Devine) rather than by an AI model.

### 🛡️ Safety Measures

- Calorie targets never fall below 1,200 kcal (women/other) or 1,500 kcal (men)
- Halal, vegetarian, vegan, gluten-free and lactose-free preferences are enforced; if a cuisine has no matching meal, a warning is shown instead of silently ignoring the preference
- The coach is instructed not to give medical advice and to refer users with injuries or conditions to professionals

### 🌙 Dark / Light Theme

GAINZ includes a theme switcher for dark and light modes.

### 📱 Responsive Design

The interface is designed to work across desktop and mobile screen sizes, with mobile navigation for smaller devices.

## 🛠️ Technologies Used

- HTML5, CSS3 and vanilla JavaScript (no framework, no build step)
- Node.js (dependency-free HTTP server)
- Google Gemini API (AI coach)
- Supabase (authentication, PostgreSQL database, Row Level Security)

## 🧠 How GAINZ Works

```text
User Profile
     ↓
Fitness Goals
     ↓
Activity & Schedule
     ↓
Food & Dietary Preferences
     ↓
Profile Review
     ↓
Generate Personalized Plan
     ↓
┌───────────────┬───────────────┐
│ Workout Plan  │   Meal Plan   │
└───────────────┴───────────────┘
          ↓
   Progress Tracking
          ↓
     AI Assistance
```

The application collects the user's profile through a four-step setup process covering profile information, activity and schedule, food preferences, and final review before generating the plan.

**Important:** the workout and meal plans are generated by a rule-based engine (`ai-engine.js`) using formulas and curated lookup tables. The Gemini model powers the AI Coach chat, which can answer questions and modify the generated plan.

## 🚀 Running GAINZ Locally

### 1. Clone the repository

```bash
git clone https://github.com/vishal-singh-62/GAINZ.git
```

### 2. Open the project

```bash
cd GAINZ
```

### 3. Set up Supabase

1. Create a project at [supabase.com](https://supabase.com) and create the six tables: `profiles`, `workout_plans`, `diet_plans`, `progress`, `workout_completions` and `water_tracking`.
2. In the SQL Editor, run `supabase-migration.sql`, then `supabase-rls.sql`.
3. Open `supabase-config.js` and paste your Project URL and publishable (anon) key from *Project Settings → API*. **Never put a `service_role` key in this file.**
4. In *Authentication → URL Configuration*, add your site URL (for example `http://localhost:3000`) so confirmation and password-reset links work.

### 4. Configure the environment

Create a `.env` file in the project root.

Use `.env.example` as a reference.

```env
GEMINI_API_KEY=your_api_key_here
```

**Never upload your `.env` file or API key to GitHub.**

### 5. Start the server

```bash
npm start
```

There are no npm dependencies, so `npm install` is not required.

The application will run locally at:

```text
http://localhost:3000
```

## 🔐 Environment Variables

GAINZ requires a Gemini API key for the AI Coach (optional `GEMINI_MODEL` and `PORT` can also be set).

The API key should be stored locally in `.env`.

The `.env` file is excluded from Git through `.gitignore`.

For other developers, `.env.example` provides the required environment variable format without exposing a secret.

## 🔒 Security Notes

- The Gemini key stays on the server in `.env`; the browser never sees it.
- The server serves only the front-end files; server code, SQL and config files return 404.
- AI endpoints are rate-limited (20 requests per minute per IP) and request bodies are size-limited.
- All user data tables are protected by Row Level Security (`supabase-rls.sql`).
- The coach endpoint is not tied to a user session. Before a public deployment, verify the Supabase access token on the server.
